# Upstream merge, 2026-10-11

This fork incorporates upstream v0.1.42, commit
`61b3fb5dd3f1e8ec09cf7e4e05208bc6d3c46406`, dated 2026-10-10.
The fork previously ended at `3752a4eff90f3f0c7b9c75b10c509893779d69ce`,

## History

Upstream rewrote its history, so the two main branches had no common Git ancestor.
The fork's original v0.1.38 commit, `99f3dbd0b21d1401b3769e0c0d963913607f380b`,
and upstream's rewritten commit, `09817da3979abfeb5fbdef7c8f1223d120c1ad39`,
have the same tree: `b430923af1caa6c1d497c33364e7a6f8e07ef834`.
An ancestry-only merge links those histories without changing any files. The next
merge brings in upstream main using that shared base. The fork's existing commits
remain in history; no force push is needed. Future upstream updates can use a normal
merge unless upstream rewrites history again.

## Fork changes

- The automatic disk chunk cache, its background writer, chained files and legacy
  argument aliases remain. Its prompt cuts now include upstream's message and pinned
  checkpoints. A deeper prefix held in a batch slot wins over a disk entry, as live
  and parked RAM prefixes do.
- Comma-separated per-card VRAM reserves remain. A comma list takes precedence over
  upstream's `--vram-reserve-later-mib`; a single reserve can use that later-card override.
- Dense stage trimming remains enabled by default for a layer split, using upstream's
  loaders and stage-size accounting. Explicit splits trim every card. With `auto`,
  upstream loads CUDA0's full dense arena before placement for the prompt path's PLE
  tables, and loads later cards' layer ranges after placement. This differs from the
  fork's earlier automatic placement, which deferred CUDA0's weights too.
- Upstream's resident RAM mode supports layer splits and copies evicted experts from
  their owning GPU. Its newer lend-region sizing replaces the fork's overlapping code.
  Setup keeps resident mode with modern engines and retains upstream's compatibility
  fallback for engines older than that support.
- The 542 files added by the fork under `bench/`, `evaluations/`, `diagnostics/` and
  `patches/` before this merge were checked against their original Git blobs and are
  unchanged.
- The instruction to never stop or restart the running server or engine remains,
  as do the saved MTP comparison and the full-vocabulary instructions.

# Upstream merge, 2026-10-17

This fork incorporates upstream main at v0.1.45, commit
`477ac13cbe8e582c20484871ce459d20d82df09d`, dated 2026-10-16.
It adds 651 commits since the previously merged v0.1.42
(`61b3fb5dd3f1e8ec09cf7e4e05208bc6d3c46406`). The fork previously ended at
`b746d61d`. This is a normal merge; existing commits and historical tags remain.
Upstream's rewritten tags v0.1.0 through v0.1.38 were not substituted for the
fork's original tags.

## Changes brought from upstream

The update includes Qwen3.6 support, Apple Silicon's Metal backend, more quantization
paths, and fixes to setup, serving, conversation reuse, multi-GPU placement and GPU
backends. The upstream sources and documentation describe their requirements and
measurements. These changes have not been benchmarked on this PC.

## Fork integration

- The disk chunk cache, background writer, chained files and legacy argument aliases
  remain. RAM and batch-slot prefixes still take precedence over shorter disk entries.
  Disk restore coexists with upstream's borrowed conversation prefixes and optional
  park-gain setting.
- Disk snapshots now select the GPU that owns the draft state. Upstream can place
  MTP on the first GPU; the old cache assumed the last GPU. The existing snapshot
  round-trip test now covers both placements, including invalid later-stage payloads
  being rejected before the first stage is written.
- Upstream's optional merged admission window is disabled while the disk cache is
  enabled: a disk checkpoint must capture all tokens at its advertised boundary.
  With the disk cache disabled, upstream's admission rule remains.
- Comma-separated per-card VRAM reserves remain, including the automatic placement
  calculation with upstream's first-GPU drafter. Setup's new small-card fit estimate
  uses the first reserve when a comma list is supplied.
- Dense stage trimming remains enabled for a layer split, using upstream's weight
  loading and placement paths.
- The 543 files previously added by this fork under `bench/`, `evaluations/`,
  `diagnostics/` and `patches/` were checked against their Git blobs and are unchanged.
  The server protection and full-vocabulary instructions in `AGENTS.md` remain.

## Validation

The tests use temporary settings; setup was not run on the installed model.
Mock HTTP tests need localhost listeners, so they were run outside the restricted
sandbox after its socket restrictions prevented them from starting.

- Installer unit tests: 604 run, passed, one skipped.
- Server unit tests: 855 run, passed, 11 skipped; fake engines, no model inference.
- Other tool unit tests: 229 run, passed, one skipped. Live-engine cache smoke tests
  and model benchmarks were excluded.
- Python source compilation passed for 198 files.
- The installer golden fixture failed eight comparisons on unchanged upstream too:
  it recorded Windows vision executable names and a 12-thread CPU. The test now
  normalizes the vision executable name and mocks that CPU count. The stored golden
  configs and production setup behavior were not changed.

- CUDA engine build passed with GCC 13.3.0, CUDA 13.0.88, Release mode and
  architectures 89 and 120. The binary is
  `/tmp/strata-upstream-v0.1.45-build/strata`; its `--help` check passed.
- Sixteen focused CTest targets passed: conversation cache, split failure, RAM
  accounting, disk chunks, session files, save reclaim, snapshots, snapshot
  validation, transfer handling, file expert sources, split lend complements,
  conversation retention, message boundaries, split rings, draft KV planning and
  batch groups. The separate dense placement test passed too.
- The snapshot test passed 4,087 checks. Disk state round trips used both the
  RTX 5070 Ti and RTX 4060, with MTP on the first GPU and on the last GPU.

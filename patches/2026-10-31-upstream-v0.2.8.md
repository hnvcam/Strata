# Upstream integration, 2026-10-31

This integration brings upstream v0.2.8, commit
`870aedd9e1ebe1c91f94da93b59af17729f6c5c0` (2026-10-29), into the fork at
`a548929b59a57101e942c3fa0cee393d82fd0cda`. It is a normal merge, preserving
both histories. There are 2,322 upstream commits since the fork's previously
merged v0.1.45 (`477ac13cbe8e582c20484871ce459d20d82df09d`), including merges.
The app and Terminal release is 0.2.8; the Qwen engine is 0.1.54.

## Changes from upstream

The update includes conversation-cache identity and shared-prefix fixes,
CUDA graph allocation recovery, later-card reserve accounting, automatic
expert-cache headroom, tool-call parsing and recovery, and Qwen3.6 sampling
bounds checks. It also brings the new Terminal and desktop application,
DeepSeek support and backend changes. Upstream's release notes and source
contain their hardware requirements and measurements. No performance or
model-quality measurement was made for this integration.

Upstream changes some defaults. In particular, covered native IQ formats
use fused int8 prefill on sm_120, and tool-call recovery is enabled. Prefill
rounding and generated tokens can differ from v0.1.45. `STRATA_PF_FUSED=0`
selects MMQ; the integration does not write that override into the user's
config. This is not a claim that the release is byte-identical to v0.1.45.

## Fork integration

- Persistent disk chunks, the background writer, reflink chains, logical and
  filesystem accounting, and legacy config/argument aliases remain.
  Live, parked and batch-slot RAM prefixes retain precedence over shorter disk hits.
- Disk checkpoints remain explicit prompt cuts. The optional merged first
  admission window stays disabled when disk caching is enabled, so a saved
  checkpoint contains every token at its advertised boundary.
- An explicit `--mtp-draft-vocab FILE` is included in disk-cache artifact
  identity, accounting for the new upstream draft-vocabulary override.
- Comma-separated per-card VRAM reserves remain. Upstream's tested stage
  reserve helper receives the fork's per-card value; the list takes precedence
  over the later-card override, while a single value still permits it.
- Dense stage trimming remains enabled on layer splits. Automatic splits
  keep the first card's full dense arena for PLE inputs and trim later cards.
- Qwen3.6's optional Q8 KV path and parity target remain alongside upstream's
  new bounds-checked sampling helper. The shared executable serves both Qwen
  families, as before.
- Upstream's updated documentation and test fixtures are retained. Fork
  sections were moved into the reorganized documents. The instructions to
  protect the running engine, require a key for non-local access and preserve
  the full custom draft vocabulary remain in AGENTS.md.
- All 650 files added by the fork under bench/, evaluations/, diagnostics/
  and patches/ before this merge were checked against their Git blobs and
  are unchanged. Upstream may update its own historical records.

## Validation

Validation runs from `/tmp/strata-upstream-check-20261031` with a separate
build at `/tmp/strata-v028-build`. Python tests use a temporary environment
and isolated configuration, data and state directories. HTTP fixtures use
temporary localhost ports; they do not contact the installed model server.
No model benchmarks or live-model test scripts are run.

- CUDA engine build passed with GCC 13.3.0, CUDA 13.0.88, Release mode,
  architectures 89 and 120, and K-quant MMQ enabled. Both the build executable
  and its staged copy passed `--help` without loading a model.
- All 26 selected CTest entries passed. These cover disk chunks, conversation
  cache, split failure, RAM accounting, session files, save reclaim, snapshot
  round trips (including the two-card disk path and either MTP placement),
  snapshot validation, transfer failures, copy streams, dense placement,
  file expert sources, split lending, message boundaries, split rings, draft
  KV planning, batch groups, stage reserves, automatic cache headroom,
  graph-window eviction, PLE residency, Qwen3.6 sampling and Q8 attention.
- Qwen3.6 Q8 parity also passed on CUDA device 1 (the second card): zero
  errors, maximum absolute attention error 1.24928718e-06.
- Installer tests: 882 passed, one skipped, one deselected; 354 subtests
  passed. The deselected parallel-download test also fails on unchanged
  upstream: it observes piece 0 twice where the test expects exactly once.
- The DeepSeek test fixture used setup.download's mock but the new engine
  installer uses its own signed-feed downloader. The first pass fetched engine
  packages only into temporary test folders. The fixture now mocks that
  downloader too; all 100 tests in the file pass without those downloads.
  Production download behavior is unchanged. No model weights were downloaded.
- Server suite: 1,246 passed, 14 skipped, 14,156 subtests passed on the full
  pass. Six failures came from an incomplete optional JSON-schema validator
  installation; after installing the documented optional dependency, all 56
  Responses/structured-output tests passed (27 subtests). The remaining IPv6
  loopback timeout also reproduces on unchanged upstream. The fork's eight
  disk-cache server-config tests passed separately.
- Other tool tests: 403 passed, 43 skipped, 138 subtests passed. One Docker
  entrypoint fixture fails with the same missing `--show-key` observation on
  unchanged upstream.
- Desktop host: 1,140 passed, 105 skipped, two failures. Both failures
  reproduce on unchanged upstream: the older-host app-update test and the
  Time-skip test that expects a child PID to disappear. The TypeScript check
  passed. The connector fixture now limits its search to its temporary folder:
  an installed system cloudflared previously bypassed the mock and left it
  waiting indefinitely. Production connector discovery is unchanged.
- The initial Terminal run reached 1,046 passes and 21 skips before its UI
  thread tests stalled and the test runner was interrupted. Twelve failures
  reproduce on unchanged upstream. A thirteenth, the discovery fixture, assumes
  the source checkout has no saved model config: it passes when the temporary
  checkout's tracked Qwen3.6 config is hidden for that single test, then restored.
  The active checkout's config is never moved. Remaining non-interactive

- All 910 tracked Python files compiled before the two test-fixture edits;
  the edited fixtures were then executed successfully. Whitespace checks passed for the fork integration code and documentation
  relative to upstream. Existing whitespace in imported upstream documents and

The tools' sole Docker fixture failure was also reproduced on unchanged

## Installed runtime

and the 993,280-byte full draft vocabulary were recorded before integration.

SHA-256. Validation was completed on `integrate/upstream-v0.2.8`, then main
was fast-forwarded to the tested merge at the user's request.

check found both the server and engine stopped. The tested engine 0.1.54,
its K-quant library and updated local build metadata were installed into
`engine/`. Their hashes match the validated build, and the installed engine's
`--help` check passed without loading a model. The redundant staging copy
was removed. The previous executable, library and metadata are preserved at
`engine/.runtime-backups/20261031-095306-before-upstream-v0.2.8/`.
The server and engine were not stopped or restarted by the agent; the user
starts Strata normally when ready.
